Дата первичной проверки: 27 сентября 2026 года. Этапы 1 и 2 приняты пользователем. По новой отдельной команде добавлен этап 2.1: более компактный интерфейс и сохранность последнего занятия через localStorage. Фактические результаты проверок — в [VALIDATION.md](VALIDATION.md). Редактор, дополнительные настройки, третья миссия, журнал многих занятий и экспорт остаются последующими этапами; их реализация сейчас не входит в работу.

Название продукта во всех пользовательских материалах — **GoWeinerDog**. Предлагаемое техническое имя пакета и репозитория — `goweinerdog`. Работа продолжается в текущей папке. Создание репозитория, публикация и push в этот этап не входят.

## 1. Что создаём и чему учим

GoWeinerDog — браузерная игровая лаборатория машинного обучения для школьников 12–16 лет, MVP для кейса WIT Teens «STEM без сложного оборудования». Ученик настраивает площадку и награды, записывает прогноз, обучает виртуальную таксу, проверяет её поведение и объясняет результат.

Учебный цикл: **прогноз → условия → тренировка → проверка → объяснение → новый эксперимент**. Основной вывод: алгоритм учится получать заданную награду; это может отличаться от намерения человека «дойти до домика».

Такса — узнаваемый собственный пиксельный персонаж: длинное тело, короткие лапы, вытянутая мордочка, висячие уши, небольшой хвост. В логике она занимает одну клетку. Поворот и кадры шага служат изображению, а не добавляют физику тела. Это учебная модель алгоритма, не модель психологии животных и не руководство по дрессировке.

| Понятие | Образ и подпись в интерфейсе |
| --- | --- |
| Среда 6×6 | Тренировочная площадка с дорожками |
| Агент | Такса |
| Старт | Место начала прогулки |
| Терминальная цель | Домик |
| Непроходимая клетка | Ограждение |
| Повторяемая награда | Точка с лакомством |
| Проверка стратегии | «Посмотреть путь» |

Три миссии:

1. **«Дорога домой».** На подготовленной площадке научиться достигать домика; сравнить путь и свой прогноз.
2. **«Ловушка лакомства».** Найти настройки, при которых возвращение к лакомству выгоднее завершения прогулки; изменить награды и обучить заново. Очки и достижение домика показаны отдельно.
3. **«Новая прогулка».** На другой площадке самостоятельно выбрать условия, записать прогноз и вывод. Переносятся знания ученика; Q-таблица начинается с нуля, перенос навыка таксы не обещается.

Q-learning и клетчатые симуляторы — существующие подходы. Вклад GoWeinerDog — образовательный сценарий, самостоятельные эксперименты и понятная проверка результатов.

В MVP входят редактор площадки, четыре действия движения, несколько настроек награды и обучения, настоящая Q-таблица, отдельная проверка, воспроизведение рассчитанного пути, прогноз и вывод, сравнение двух экспериментов, локальный журнал и экспорт JSON. Аккаунты, сервер, платные API, чат-бот, computer vision, физическое оборудование, нейросеть и игровой движок не нужны. Node.js нужен разработчику для сборки; ученику достаточно браузера. Установка/PWA и гарантированный запуск без сети после закрытия браузера — отдельная будущая работа.

## 3. Pixel RetroUI и визуальная система

Нужен именно **`pixel-retroui`**, официальный сайт **retroui.io**, репозиторий **Dksie09/RetroUI**. Одноимённые библиотеки не подменяют этот выбор.

Официальная инструкция описывает React/TypeScript/Tailwind и ручной импорт `pixel-retroui/dist/index.css`; цвета компонентов задаются, в частности, через `bg`, `textColor`, `borderColor`, `shadow`. У опубликованного пакета есть TypeScript-декларации и готовый CSS. Tailwind присутствует в инструментах разработки библиотеки, но не является её peer-зависимостью. В готовом CSS уже есть utility-стили и глобальный reset. Поэтому минимальный кандидат для проекта — **ручной импорт готового CSS и собственные стили без отдельного Tailwind build**. Это вывод из содержимого пакета; работоспособность сочетания ещё нужно проверить в браузере.

Порядок будущей интеграции:

1. Подключить зафиксированный пакет вручную. CLI библиотеки не нужен: он автоматически меняет настройки и предлагает собственный шрифт.
2. Импортировать CSS библиотеки перед стилями GoWeinerDog; проверить действие reset на кнопки, поля, заголовки и фокус.
3. Начать с `Button` и `Card` через тонкие компоненты-обёртки `ui/controls.tsx`, где задаются цвета, отступы и русский шрифт. У Button тень задаётся `shadow`, у Card — `shadowColor`. Поля ввода использовать только после проверки подписей, ref и передачи стандартных HTML-атрибутов; при ограничениях использовать нативные поля с тем же оформлением.
4. `fonts.css` не подключать: проверка таблиц символов опубликованных Minecraft OTF показала отсутствие кириллицы. Явно переопределить `font-family` у библиотечных компонентов на системный шрифт с кириллицей. Пиксельный характер передают изображения, рамки и тени. Позднее локальный шрифт с полной кириллицей допустим после проверки лицензии и читаемости.
5. Проверить русский текст, включая «ё», `disabled`, `aria-*`, `type="button"`, клавиатуру, видимый фокус и мобильные размеры. В опубликованных стилях Input/TextArea контур фокуса прозрачен — добавить собственный. Button и Input не предоставляют `forwardRef`, у Input `className` относится к контейнеру; учитывать это в обёртках. Popup и Dropdown в MVP не использовать из-за неполной клавиатурной модели; достаточно нативных select/details и результатов на странице.
6. Выполнить production build и открыть результат, включая модульный Web Worker. Проверить разрешение CSS и типов пакета, отсутствие конфликтующих копий React и ошибок в консоли.

Если обнаружится реальная потребность в Tailwind для выбранных компонентов, обосновать её отдельным результатом проверки. На дату исследования доступны Tailwind и `@tailwindcss/vite` 4.3.3; плагин заявляет Vite 8, но это само по себе не подтверждает совместимость старых стилей Pixel RetroUI с Tailwind 4. Не копировать настройку Tailwind 3 из старой инструкции вслепую.

Источники: [официальная установка Pixel RetroUI](https://retroui.io/installation), [API Button](https://retroui.io/button), [исходный репозиторий и лицензия BSD-3-Clause](https://github.com/Dksie09/RetroUI), [опубликованный пакет 2.1.0](https://registry.npmjs.org/pixel-retroui/2.1.0). Сведения о типах, компонентах, шрифтах и CSS проверены чтением [опубликованного архива 2.1.0](https://registry.npmjs.org/pixel-retroui/-/pixel-retroui-2.1.0.tgz), без установки. Уведомление о лицензии зависимости сохранить.

### Палитра и проверенный контраст

Контраст посчитан по относительной яркости sRGB для непрозрачных сплошных цветов. Для обычного текста ориентир — не менее 4.5:1; для крупного текста — 3:1. Значения ниже не заменяют проверку hover, focus, disabled, прозрачности и реального размера текста. [WCAG: минимальный контраст](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html).

| Текст / фон | Контраст | Применение |
| --- | --- | --- |
| Шоколад `#35231D` / кремовый `#FFF7ED` | 14.03:1 | Основной текст |
| Шоколад / белый `#FFFFFF` | 14.90:1 | Рабочие панели |
| Белый / зелёный `#365C45` | 7.57:1 | Основные кнопки |
| Кремовый / зелёный | 7.13:1 | Допустимая подпись на зелёном |
| Шоколад / золотистый `#E8AD55` | 7.48:1 | Подпись бонуса |
| Белый / карамельный `#B96E36` | 3.93:1 | Не использовать для обычного текста |
| Карамельный / кремовый | 3.70:1 | Не использовать для обычного текста |
| Шоколад / карамельный | 3.79:1 | Не использовать для обычного текста |
| Золотистый / кремовый | 1.88:1 | Только декор с тёмным контуром, не текст |

Карамельный — шерсть и отдельные акценты; золотистый — лакомство с шоколадным контуром. Статусы сопровождаются словами и различимыми значками, например «Дома» с домиком и «Лимит шагов» с часами. Зелёная заливка сама по себе не сообщает об успехе.

### Собственные изображения и компоновка

- На первом рабочем этапе создать собственный небольшой пиксельный SVG таксы, пригодный для четырёх направлений, и базовые тайлы дорожки, ограждения и домика. При необходимости позже экспортировать PNG со спрайтами; не брать чужие игровые изображения. Точку с лакомством добавить к соответствующей миссии.
- Длинный силуэт вписывать в одну логическую клетку; не закрывать соседние клетки или обозначение домика. Собаку не заменять эмодзи, роботом или случайной породой.
- Для растра использовать `image-rendering: pixelated`, для SVG — чёткие пиксельные формы. Анимация лап возможна, но перемещение определяется только записанными переходами.
- Основной экран сразу открывает площадку: короткая задача, прогноз, карта и «Начать тренировку». После обучения главное действие — «Посмотреть путь». Настройки и результаты рядом на широком экране, ниже карты на телефоне; без отдельного лендинга.
- Основной русский текст около 16 px с удобным межстрочным интервалом. Пиксельные рамки не должны сжимать полезную область. Цель для кнопок и клеток — область касания не менее 44×44 CSS px; площадка 6×6 должна помещаться на экране шириной 320 px с разумными полями.
- Редактор: выбор инструмента, затем клетки; мышь и касание без обязательного drag. Клавиатура: один вход Tab в сетку, стрелки перемещают фокус, Enter/Space применяют инструмент. Клетка имеет координаты и текстовое имя. Схему ролей и объявлений проверить в браузере.
- Доступны пауза воспроизведения, один шаг и «Сразу результат»; учитывать `prefers-reduced-motion`. Статус обучения объявлять умеренно через `aria-live`, не на каждом шаге. Рядом с картой доступен текстовый список переходов.
- Пустое состояние: «Такса ещё не тренировалась». После правки: «Условия изменились — начни новую тренировку». При непроходимой площадке: «Домик отрезан ограждениями. Освободи проход». При остановке: «Тренировка остановлена; новая начнётся с нуля».

## 4. Минимальная архитектура

Одно приложение React с разделами «Лаборатория», «Мои опыты» и «Как это работает». Лаборатория открывается по умолчанию и содержит весь учебный цикл. `LabController` управляет вычислениями; отдельное состояние занятия хранит завершённые результаты и записи. Переключение разделов не пересоздаёт контроллер. Чистая логика TypeScript не зависит от React, DOM и хранения. Worker использует ту же логику, что и тесты; UI не реализует вторую версию правил.

| Слой | Ответственность | Чего не делает |
| --- | --- | --- |
| `domain/environment` | Один переход, столкновение, награда, достижение домика | Не обучается и не рисует |
| `domain/validation` | Формат площадки, параметры, BFS-достижимость | Не передаёт маршрут алгоритму |
| `learning` | PRNG, выбор действия при обучении, Q-update, эпизоды | Не знает компонентов и localStorage |
| `evaluation` | Детерминированный проход по замороженной Q | Не обучается и не исследует случайно |
| `missions` | Условия, пресеты, тексты и вопросы трёх миссий | Не содержит готовых маршрутов таксы |
| `workers` | Запуск вычислений и сообщения прогресса | Не меняет UI или журнал напрямую |
| `app` | Состояния, сброс, отмена, соответствие результата условиям | Не рассчитывает награды |
| `ui` | Площадка, настройки, прогноз, метрики, воспроизведение | Не придумывает числа или движения |
| `experiments` | Неизменные снимки расчётов, редактируемые наблюдения, сравнение и последнее занятие в localStorage; журнал и экспорт — этап 4 | Не меняет сохранённые условия, Q и метрики задним числом |

### Контракты данных

- `EnvironmentConfig`: размер, start, home, fences, optional treat, награда за шаг, столкновение, вход домой и вход к лакомству. Координаты объектов различны, ограждения их не перекрывают.
- `TrainingConfig`: число эпизодов, предел шагов, alpha, gamma, расписание epsilon, seed и идентификатор PRNG. Проверяются конечные числа, `0 < alpha ≤ 1`, `0 ≤ gamma < 1`, `0 ≤ epsilon ≤ 1`, положительные целые эпизоды/лимиты и безопасные верхние пределы. Seed — целое в документированном диапазоне uint32; алгоритм PRNG и поведение seed 0 фиксируются тестом. Пустой ввод не превращается молча в ноль.
- `Transition`: клетка до/после, действие, общая награда и её составляющие, `moved`, `collision`, `enteredTreat`, `terminated`.
- `TrainingResult`: Q-таблица, метрики реальных эпизодов, число обновлений, снимок конфигурации, версия алгоритма и seed. Время выполнения — отдельная служебная метрика, не часть воспроизводимого результата.
- `EvaluationResult`: фактические переходы и позиции, очки, шаги, число входов к лакомству, столкновения, `goal` либо `timeout`. Отмена имеет отдельный статус операции; её нельзя выдавать за timeout или законченную проверку.
- `ExperimentSnapshot` (этап 2): id, миссия, собственные копии завершённой модели с условиями, проверки с лимитом, прогноза и наблюдения. При фиксации результат сверяется с моделью; всё содержимое глубоко замораживается. Общий вывод по паре хранится отдельным полем текущего сеанса.
- `Experience` (этап 2.1): тот же независимый завершённый расчёт для обеих миссий. Условия, модель и результат глубоко заморожены. Дописывание наблюдения создаёт новую версию записи с теми же неизменными данными расчёта; прогноз, записанный до старта, остаётся прежним. Все места показа одного id обновляют наблюдение согласованно.
- `LessonState` (этап 2.1): версия 1, выбранная миссия, черновики, завершённый результат «Дороги домой», текущий опыт, рабочая пара и последняя сохранённая пара с объяснением. Состояние ограничено этими записями, без растущего журнала. Текущий опыт ссылается на одну из записей; восстановление проверяет совпадение его условий и записей с активным черновиком.
- `ExperimentRecord`: версия схемы, id/дата, миссия, независимые копии всех условий и модели, метрики, проверенный путь, прогноз и вывод, версия алгоритма/PRNG/порядка действий. Текущие элементы управления не являются источником условий старой записи.

## 5. Правила среды и обучения

### Среда

Состояние — индекс клетки `y × width + x`. Для 6×6 максимум 36 состояний × 4 действия = 144 значения Q. Четыре действия в фиксированном порядке: вверх, вправо, вниз, влево. Нет отдельного действия «стоять». Направление взгляда персонажа не влияет на среду.

Один вызов `step` выполняет ровно одно действие. Выход за границу или движение в ограждение оставляет таксу в той же клетке, учитывается как шаг и столкновение. Награда складывается явно:

`за шаг + штраф столкновения (если было) + за вход к лакомству (если был) + за вход домой (если был)`.

Лакомство выдано только если позиция действительно изменилась и новая клетка — точка с лакомством. Бонус даётся при каждом входе, включая первый; возвращение после выхода снова даёт бонус. Столкновение, ожидание интерфейса, пауза анимации и сам старт эпизода не дают бонуса. В редакторе старт, домик и лакомство не совмещаются. После достижения домика новые переходы не выполняются и награда повторно не начисляется.

Валидация: размер 6×6, один старт и один домик, не более одной бонусной клетки, корректные координаты, допустимые награды. BFS проверяет существование пути до обучения. Отсутствие пути блокирует запуск с понятным сообщением. Недоступность лакомства — объяснимое предупреждение; в миссии с ловушкой пресет обязан иметь доступное лакомство. BFS может дать длину кратчайшего пути как подписанный ориентир, но не начальные Q, действия обучения или данные воспроизведения.

Если путь существует, но выбранный лимит меньше его кратчайшей длины, заранее показать: «За N шагов домик недостижим; нужно не менее D». Это ограничение условий, а не свидетельство плохого обучения. Проверять отдельно лимит тренировки и проверки; равенство лимита кратчайшей длине допускает достижение цели на последнем шаге.

### Почему это машинное обучение

Q-таблица — небольшая «тетрадь оценок»: для каждой клетки хранится оценка четырёх действий. Сначала там нули. Такса пробует действие, получает настоящую награду от среды и меняет оценку на основе опыта. Поведение формируется из этих обновлений, без заранее заданного правильного пути. Это обучение с подкреплением; нейросеть — лишь один из возможных способов хранить оценки, а здесь маленькой таблицы достаточно. [Исходная работа Watkins и Dayan о Q-learning](https://www.gatsby.ucl.ac.uk/~dayan/papers/cjch.pdf).

Правило:

`Q(s,a) ← Q(s,a) + α × [target − Q(s,a)]`

- При входе домой: `target = r`.
- Для остальных переходов: `target = r + γ × max Q(s′,a′)`.

Здесь `r` — полученные очки шага, `α` — насколько сильно новый опыт меняет оценку, `γ` — насколько учитываются будущие награды. Значение `γ` держать меньше 1, особенно при повторяемом бонусе. В интерфейсе сложные настройки убраны в раскрываемый раздел с этими объяснениями.

При тренировке использовать epsilon-greedy: иногда попробовать случайное действие, иначе выбрать действие с наибольшей оценкой. Все случайные решения, включая выбор среди равных оценок при обучении, идут через один явно переданный seeded PRNG. Epsilon меняется по номеру эпизода, не по времени компьютера. PRNG не пересоздаётся с тем же seed на каждом эпизоде. Между эпизодами позиция возвращается на старт, Q сохраняется; перед новым обучением Q обнуляется.

### Домик и лимит шагов

Выбранная модель: домик — настоящий конец задачи (`terminated`), лимит шагов — внешнее ограничение длительности попытки (`truncated`). В последнем разрешённом шаге сначала выполняется переход: если достигнут домик, это успех, даже на границе лимита. Иначе фиксируется timeout.

При timeout **сохраняется будущая оценка** в Q-update по фактической следующей клетке; она не подменяется стартовой клеткой следующей попытки. Новая попытка начинается отдельно. Это позволяет хранить состояние только как клетку. Если бы оставшееся время было частью правил самой задачи, его пришлось бы включить в состояние — такой вариант в MVP не выбираем. [Документация Gymnasium о terminal и truncation](https://gymnasium.farama.org/tutorials/gymnasium_basics/handling_time_limits/).

Сумма очков за ограниченную попытку и дисконтированная оценка будущих наград Q — разные величины. Подписывать их соответственно; ученику по умолчанию показывать очки, домик и число шагов, а не внутренний `max Q` как «успех».

### Проверка и воспроизведение

- Проверка принимает завершённую модель и её снимок среды, стартует с исходной клетки и выбирает только максимум Q. Никаких вызовов PRNG и epsilon; равенства разрешаются фиксированным порядком действий.
- Q доступна только для чтения, а тест проверяет полное равенство до/после. Проверку выполнять по тому же `environment.step`, что используется в обучении.
- Результат ограничивается шагами и честно может закончиться timeout, столкновениями или циклом. Повтор клетки можно отметить как обнаруженный цикл; не сокращать из-за этого скрытно путь, награду и лимит.
- Сначала рассчитать и сохранить весь результат проверки, затем воспроизводить его переходы. Кнопка повтора читает тот же массив; пауза и скорость не обучают, не выбирают действия и не меняют очки. Столкновение показывается на месте, а не как переход в соседнюю клетку.
- Повторный просмотр или повторная детерминированная проверка одной Q-таблицы не являются независимыми испытаниями. Для оценки повторяемости запускать отдельные обучения с нулевой Q и заранее выбранным набором разных seed. Повтор одного seed проверяет воспроизводимость.
- Один seed + одинаковые условия, алгоритм/PRNG, порядок действий и число обновлений должны давать одинаковые Q, метрики и путь. UUID, дата, время выполнения и частота сообщений UI могут отличаться. Визуальные эффекты не расходуют случайную последовательность обучения.

## 6. Операции, отмена и сброс опыта

Вычисления обучения и проверки выполняет модульный Web Worker. Главный поток рисует интерфейс. Прогресс отправлять порциями, например после пачки эпизодов, с ограничением частоты; частота сообщений не влияет на математику. Полную Q передавать по завершении, а не после каждого шага. График использует фактические метрики завершённых эпизодов; окно усреднения и количество эпизодов подписаны.

Состояния приложения: `idle → training → trained → evaluating → ready`; отдельно `cancelled` и `error`. Воспроизведение — самостоятельное состояние поверх готового результата. В журнал попадает завершённый снимок, не ссылка на изменяемое состояние.

- Каждая операция получает `runId` и номер версии условий. Сообщение принимается только от актуальной операции и для актуальных условий.
- «Остановить», смена миссии, начало новой тренировки, изменение условий и размонтирование завершают старый Worker через `terminate()`, инвалидируют `runId` и отменяют воспроизведение. Одного сообщения `cancel` недостаточно, если Worker занят синхронным циклом.
- Частичный результат отменённого обучения не становится готовой моделью; следующая тренировка начинается с нуля. Незавершённая проверка не становится готовым маршрутом. Отмена проверки/просмотра сама по себе не обязана удалять уже завершённую Q при неизменных условиях.
- Изменение карты, наград, seed, числа эпизодов, alpha/gamma, epsilon или лимитов сбрасывает текущую Q, метрики и проверку. Изменение прогноза, вывода, громкости (если появится) или скорости просмотра не сбрасывает обучение. Никаких скрытых продолжений старой Q на новых условиях.
- Поля настроек во время вычисления можно блокировать с пояснением «Сначала останови тренировку»; смена миссии и остановка остаются доступны и корректно отменяют работу. Правило инвалидирования всё равно действует на программные изменения.
- Завершённая проверка автоматически создаёт опыт до сброса текущей операции. Изменение бонуса до ручного действия не теряет первый результат. Условия, Q, путь и метрики сохранённого опыта остаются прежними; наблюдение можно дописать.
- Начиная с этапа 2.1 смена миссии отменяет Worker и просмотр, сохраняя завершённые опыты и черновики. Переключение разделов сохраняет занятие и не обрывает Worker. Первая завершённая пара сохраняется автоматически; следующая рабочая пара существует отдельно. Последняя сохранённая пара и её объяснение остаются до явной замены новой готовой парой или «Начать заново».
- Перезагрузка восстанавливает проверенные завершённые результаты и записи из localStorage. Незавершённый Worker, промежуточная Q и кадр анимации не восстанавливаются. Прежнее правило этапа 2 об очистке всего сеанса при перезагрузке отменено отдельным запросом этапа 2.1.
- Проверить cleanup с React Strict Mode: не оставлять два Worker, таймеры или подписки после повторного запуска эффекта.

## 7. Эксперименты и честные метрики

В этапах 2 и 2.1 в ловушке изменяется только целый бонус за лакомство от 0 до 10. Seed фиксирован на 42; остальные награды, число эпизодов, лимиты и параметры обучения доступны для просмотра. «Дорога домой» сохраняет отдельный пресет и возможность изменить seed. На этапе 3 появятся дополнительные настройки: «Награда за возвращение домой», «Цена шага», число тренировочных попыток и seed с объяснением «Повторить ту же случайность». Значения ограничены и имеют единицы/описания; не разрешать неограниченные вычисления.

Результаты разделены:

- **Тренировка:** выполненные эпизоды, фактические очки и шаги, сколько эпизодов достигли домика; исследование среды ещё включено.
- **Проверка:** «Добралась ли такса домой?», набранные очки, шаги, входы к лакомству, причина окончания. Это один детерминированный проход конкретной стратегии.
- **Вывод ученика:** «Что ты ожидал?» и «Чему научилась такса? Почему?». Прогноз предлагается до старта, вывод — после проверки; пропуски помечаются, не заполняются автоматически. Изменение прогноза после старта отмечать как позднюю правку, чтобы не выдавать её за предварительный прогноз.

Последнее занятие (этап 2.1): JSON с `version: 1` под ключом `goweinerdog.lesson.v1`. Сохраняются условия, Q, метрики эпизодов и проверенный путь завершённых опытов, черновики и учебные записи. Количество записей ограничено структурой занятия; ввод ограничен, размер JSON перед чтением ограничен 1 500 000 символов. При восстановлении проверяются версия, фиксированные пресеты, значения Q, завершённость метрик, согласованность копий одного id и соответствие пути детерминированной проверке модели. Обучение заново для восстановления не запускается.

Сохранение происходит при изменении занятия, не на кадрах анимации и не на каждом сообщении Worker. Недоступный localStorage, повреждённый JSON, неизвестная версия и превышение квоты дают предупреждение; успешное сохранение не заявляется. При ошибке записи рассчитанные результаты остаются в памяти вкладки. Чтение повреждённых данных само по себе их не перезаписывает; пользователь может начать новое занятие. Личные данные не нужны. Занятие остаётся в этом браузере для этого адреса и может исчезнуть при очистке данных.

Журнал многих занятий (этап 4): расширить ограниченное хранение отдельными JSON-записями с версией схемы, выбором записей для сравнения и выгрузкой. Ограничить размер и число записей, не удалять старые молча. Это расширение ещё не реализовано; при ошибке хранения текущий интерфейс не предлагает отсутствующий экспорт.

Экспорт (этап 4): JSON с версией схемы, условиями, моделью, прогнозом, выводом, фактическими метриками и переходами; человекочитаемые подписи в UI. Импорт и CSV не обязательны для MVP. Проверка экспорта подтверждает, что скачанный JSON содержит тот же эксперимент; даты или подписи не вычисляют метрики заново.

Сравнение ровно двух записей: рядом площадки, награды, параметры обучения, seed, версии алгоритма и лимиты; отдельно список **всех различающихся условий**, включая координаты объектов. Затем очки, домик, шаги и выводы. Разные карты и лимиты не прятать за общим рейтингом. Если изменено несколько условий, написать, что причину нельзя уверенно приписать одному. Для учебного эксперимента предлагать менять один параметр и обучать заново; одинаковый seed полезен для контролируемого сравнения, разные seed — для проверки повторяемости.

## 8. Этапы разработки и критерии готовности

### Этап 0 — планирование, завершён

Результат этапа планирования: осмотр папки, проверка версий и документации, архитектура, правила корректности, последовательность и риски. На момент завершения этапа 0 кода и зависимостей не было. Фактическая реализация и проверки этапа 1 описаны в `docs/VALIDATION.md`. Публикации нет.

### Этап 1 — одна площадка → тренировка → проверка → настоящий путь; завершён и принят

Минимальный законченный результат: один экран с узнаваемой таксой и одной фиксированной площадкой «Дорога домой», настоящая тренировка в Worker, отдельная проверка, реальные метрики и воспроизведение. ```text

. # . # . .
. # . . . .
. . . # . .
# # . # . .
. . . . . H

Начальный кандидат пресета: 800 эпизодов, максимум 100 шагов на эпизод и проверку, seed 42, alpha 0.2, gamma 0.95, epsilon от 1.0 до 0.05 за первые 80% эпизодов, затем 0.05. За шаг −1, дополнительный штраф столкновения −1, дополнительная награда дома +20, бонус отсутствует. Это стартовая гипотеза для проверки, а не измеренный рецепт успеха. Везде фиксировать, что награда дома добавляется к цене шага.

### Этап 2 — минимальная «Ловушка лакомства» на подготовленной карте; реализован

Описание ниже фиксирует принятый этап 2. Его прежние правила ручной фиксации, замены второго опыта и очистки при перезагрузке заменены требованиями этапа 2.1; настройки алгоритма сохранены.

Этап реализован сразу после первой работающей площадки: добавлены подготовленная карта с лакомством, изменение только размера бонуса, новое обучение с нуля и сравнение двух результатов в памяти текущего сеанса. Остальные условия фиксированы и видны. Прогноз, очки, достижение домика и объяснение показывают учебный цикл «ожидание → поведение → изменение награды → новая проверка». Редактор, постоянный журнал, экспорт и дополнительные настройки в этап 2 не входят.

Исходный аналитический кандидат ловушки: площадка 6×6, один доступный прямой коридор из шести клеток, прочее — ограждения; старт в позиции 0, лакомство в 1, домик в 5. За шаг −1, дома дополнительно +12, лакомство +5, gamma 0.9, дополнительный штраф столкновения −1. Из клетки лакомства дисконтированная оценка четырёх шагов домой: `−1 − 0.9 − 0.81 + 0.729 × 11 = 5.309`. Цикл «сосед → лакомство» имеет оценку `(−1 + 0.9 × 4) / (1 − 0.9²) ≈ 13.684`. При бонусе +1 оценка такого цикла становится примерно −5.263, тогда как путь домой сохраняет оценку 5.309. Это аналитическое обоснование; фактическая проверка обучением приведена ниже.

Кандидат подтвердился без изменений условий и без неудачных обучений на заранее выбранном наборе **0, 1, 7, 42, 2026, 65535**. Выполнены 12 отдельных обучений с нуля: для каждого seed при +5 получены timeout, 150 очков, 100 выполненных шагов и 50 входов к лакомству; при +1 — домик, 8 очков, 5 шагов и 1 вход. Готовые Q, маршрут или анимация не подставлялись. Фиксированные условия: 800 эпизодов, по 100 шагов максимум; проверка тоже ограничена 100 шагами; alpha 0.2; gamma 0.9; epsilon от 1 до 0.05 линейно за первые 640 эпизодов, затем 0.05. В UI seed равен 42. У «Дороги домой» сохранены собственные настройки: домик +20, gamma 0.95; ловушка их не меняет.

Готовность: настоящие отдельные обучения на фиксированном наборе seed демонстрируют цикл при исходных условиях и домик после исправления. При высоких очках и timeout UI прямо показывает «До домика не дошла». Лакомство начисляется при каждом входе, включая первый, но не за стояние или столкновение. Смена миссии сбрасывает текущий опыт и останавливает предыдущую работу; зафиксированные снимки сохраняются. При будущих изменениях пресета заново проверить весь набор seed, включая возможные неудачи; анимацию и Q не подменять.

В первоначальном этапе 2 два результата в памяти содержали собственные условия, Q, рассчитанный путь, прогноз и наблюдение. При ручной фиксации создавался независимый замороженный снимок. Сравнение выделяло изменённый бонус и проверяло совпадение остальных условий; старый путь использовал собственную среду и метрики. Перезагрузка очищала сеанс, новая тренировка заменяла второй опыт. Эти ограничения устранены в этапе 2.1. На момент принятия этапа 2 прошли typecheck, 125 модульных тестов, production build и 18 браузерных сценариев; история и текущие проверки — в [VALIDATION.md](VALIDATION.md).

### Этап 2.1 — компоновка и сохранность последнего занятия

Отдельно разрешённая доработка существующих двух миссий. Добавлены три раздела: «Лаборатория» открывается по умолчанию и содержит полный цикл эксперимента; «Мои опыты» использует тот же компонент сравнения и те же данные; «Как это работает» объясняет обучение простыми словами. На компьютере — узкая боковая навигация, площадка и компактные действия рядом; на телефоне — компактная навигация, крупная площадка и адаптированное сравнение. Seed, координаты и параметры доступны в «Подробнее». Небольшой индикатор показывает текущий учебный шаг, основное действие подсказывает следующий.

Представление ловушки показывает только открытый коридор, сохраняя логику площадки 6×6, координаты и все реальные переходы. Добавлены заметное «Сразу результат» и ускоренный просмотр без изменения вычислений. Русский текст, собственная пиксельная такса и лакомство, Pixel RetroUI, палитра, reduced motion и клавиатурное управление сохраняются. Новые зависимости не требуются.

Завершённый опыт сохраняется автоматически до изменения условий. Наблюдение можно дописать без изменения модели и метрик. Первая завершённая пара сохраняется автоматически; следующий эксперимент не удаляет её и итоговое объяснение. Новая полная пара заменяет прежнюю только явным действием. Последнее занятие восстанавливается через проверяемый localStorage; ошибки чтения и записи не ломают приложение и не выдаются за успех. Работающий Worker и незавершённое обучение не восстанавливаются.

Критерии готовности: изменение бонуса до ручного действия сохраняет первый опыт; завершённая пара переживает следующий запуск и отмену; смена раздела сохраняет текст и расчёт; смена миссии отменяет расчёт и сохраняет опыты; после перезагрузки восстановлены завершённые результаты и записи; повреждение и недоступность хранилища обработаны; старый путь использует собственные условия. Полный сценарий, ширины 320/375/1280 px, клавиатура, фокус, reduced motion, типы, тесты и production build проверяются с записью фактических результатов в [VALIDATION.md](VALIDATION.md).

Граница этапа: только компоновка и сохранность последнего занятия. Редактор, третья миссия, новые параметры обучения, большой журнал и экспорт не добавляются. После выполнения этих критериев работа останавливается до следующей команды.

### Этап 3 — редактор, дополнительные настройки и «Новая прогулка»

После проверки минимальной ловушки добавить выбор старта/домика/ограждений/лакомства, дополнительные настройки наград и обучения, проверку ввода и объяснения параметров. Добавить «Новую прогулку» на другой площадке и самостоятельные эксперименты, график фактических эпизодов.

Готовность: нельзя запустить непроходимую или некорректную карту; после каждой значимой правки старая модель недоступна; при воспроизведении старая карта не смешивается с новой; редактор доступен клавиатурой и касанием. Поле с невалидным вводом сообщает причину и не запускает Worker. На новой площадке обучение начинается с нулевой Q.

### Этап 4 — журнал, сравнение и выгрузка

Расширить уже реализованное хранение последнего занятия до ограниченного журнала нескольких занятий: выбор старых записей, сравнение выбранной пары и экспорт JSON. Базовое восстановление через localStorage уже входит в этап 2.1. Просмотр старой записи использует её собственную площадку и путь; действие «Повторить условия» заполняет новый эксперимент и начинает обучение с нуля.

Готовность: после перезагрузки записи сохраняются; новая правка не меняет старую; экспорт совпадает с записью; различия условий видны полностью; сбой хранения не теряет текущий результат в памяти и не выдаётся за успешное сохранение.

### Этап 5 — проверка целого MVP и демонстрация

Пройти все три миссии от прогноза до вывода, локального сохранения, сравнения и выгрузки. Проверить мобильную компоновку, клавиатуру, контраст фактических состояний, отмену и ошибки. Подготовить короткий сценарий выступления с честным объяснением Q-learning и ловушки. Зафиксировать протестированные браузеры, версии, пресеты и известные ограничения.

Готовность: все перечисленные ниже проверки выполнены и их результаты записаны, основной браузерный сценарий проходит, для демонстрации не требуется сервер приложения или внешний API. Статическая сборка готова к возможной публикации, но сама публикация и push выполняются только по отдельной команде.

Для оценки повторяемости записывать число отдельных обучений, их seed, условия и результат каждого. Долю достижений на конкретном наборе так и подписывать. Не использовать повторное проигрывание одного пути как статистику и не обещать универсальность, точность или надёжность до измерений.

## 10. Риски и решения

| Риск | Что делаем |
| --- | --- |
| Папка не связана с Git | Сохраняем план здесь; Git/remote не придумываем. При отдельной команде на Git сначала уточняем или проверяем существующий источник |
| Старый Pixel RetroUI + новые React/TS/Vite | Ранний минимальный smoke-test типов/CSS/сборки; версии фиксируем; UI-обёртки локализуют исправления |
| Глобальный CSS и неполная доступность библиотеки | Проверяем reset, фокус, атрибуты и формы; при необходимости нативные поля с общей темой |
| Пиксельный шрифт плохо читает кириллицу | Системный шрифт для текста; собственные пиксельные изображения для характера |
| Такса неузнаваема или перекрывает карту | Проверяем силуэт на размере реальной клетки и на телефоне до множества анимаций |
| Награды не дают желаемого учебного примера | Обосновываем пресет, затем проверяем реальным обучением на нескольких seed; не подменяем результат |
| Формула ошибочно считает timeout терминалом | Явное разделение флагов и независимые численные тесты |
| Высокие очки выглядят как успех задачи | Отдельные метрики очков и домика, вопрос о причине поведения |
| Всплывает результат старой операции | terminate, runId, версия условий, тесты гонок и cleanup |
| Долгая работа тормозит телефон | Worker, ограниченные бюджеты, порционные метрики, измерение на доступных устройствах; без обещаний скорости заранее |
| localStorage переполнен или очищен | Ограниченное последнее занятие, честные сообщения и результат в памяти вкладки; экспорт JSON появится только на этапе 4 |
| Срок хакатона ограничен | Сначала этап 1 целиком, затем минимальная ловушка и сравнение в памяти; после проверки этого цикла — редактор, дополнительные настройки, постоянный журнал и экспорт. Сокращать декор, не корректность алгоритма |

## 11. Что ученику-разработчику нужно понимать на первом этапе

1. **Среда отвечает за правила.** Она получает клетку и действие и возвращает результат. Если здесь ошибка в бонусе, алгоритм честно выучит ошибочные правила.
2. **Q — оценки действий, не маршрут.** Маршрут появляется только когда мы последовательно выбираем действия и применяем правила. Маленькую таблицу можно посмотреть и вручную проверить одну её запись.
3. **Эпизод — одна попытка.** Между попытками такса возвращается на старт, но помнит Q. Новая тренировка начинается с пустой таблицы.
4. **Случайные попытки нужны в обучении.** Без исследования такса может не узнать о хорошем пути. Seed позволяет повторить тот же набор случайных решений.
5. **Проверка — отдельный проход.** Она показывает уже выученное, ничего не дописывает в Q и не ищет случайно другой путь. Повторный просмотр показывает те же данные.
6. **Домик, очки и лимит — разные вещи.** Много очков не гарантируют домик. Лимит защищает от бесконечной прогулки и не означает, что задача выполнена.
7. **UI отображает расчёт.** Движение на экране, число шагов и очки обязаны совпасть с массивом переходов. Красивое движение не доказывает обучение.

Проверять вместе: посчитать одно обновление Q на бумаге; сопоставить первые переходы с клетками; сложить награды; повторить seed; остановить тренировку и начать снова; увидеть, что модель не меняется при проверке. Перед запуском записать ожидание, после — объяснить наблюдение без выдуманных намерений животного.

## 12. Граница текущей реализации

Текущая отдельная команда разрешила **только этап 2.1** в существующем проекте: упростить интерфейс → добавить три раздела с общим сравнением → сохранять завершённые результаты до сброса → отделить следующий эксперимент от последней сохранённой пары → восстановить последнее занятие через проверяемый localStorage → проверить сценарии и доступность → записать фактические результаты. Алгоритм, Web Worker, обе миссии и подтверждённые пресеты сохраняются. Следующий этап 3 — редактор, дополнительные настройки и «Новая прогулка» — начинается только по отдельной команде. Журнал многих занятий и экспорт остаются в этапе 4. Git, публикация и push не выполняются.
