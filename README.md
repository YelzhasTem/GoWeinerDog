# GoWeinerDog

Публичная версия для тестирования: **[goweinerdog.vercel.app](https://goweinerdog.vercel.app/)**. Сайт размещён на Vercel и открывается без аккаунта приложения или входа в Vercel.

Игровая лаборатория машинного обучения для школьников 12–16 лет: виртуальная такса учится действовать на площадке 6×6. Реализованы «Дорога домой», минимальная «Ловушка лакомства» и доработка интерфейса с восстановлением последнего занятия. Настоящее табличное Q-learning, отдельная проверка, Web Worker и проверенные настройки обеих миссий сохранены.

В ловушке ученик меняет только бонус за лакомство, обучает таксу с нуля и сравнивает два опыта. Остальные условия фиксированы и доступны для просмотра. Большое число очков само по себе не означает, что такса добралась домой. Это учебная модель алгоритма, а не симулятор психологии животных или руководство по дрессировке.

В приложении три раздела:

- **Лаборатория** открывается по умолчанию. Здесь проходит весь цикл: прогноз → обучение → наблюдение → изменение бонуса → второй опыт → сравнение и объяснение.
- **Мои опыты** показывает сохранённую пару и результат «Дороги домой». Можно посмотреть прежний путь с его условиями и дописать наблюдение. Компонент сравнения общий с лабораторией.
- **Как это работает** объясняет попытки, награды, обучение и проверку; подробности Q-learning раскрываются по желанию.

На компьютере навигация находится сбоку, площадка и действия — рядом. На телефоне разделы расположены компактно сверху. В ловушке крупно показана открытая дорожка: остальные 30 ограждённых клеток скрыты только в представлении. Среда остаётся 6×6, координаты и рассчитанный путь не меняются. Длинный путь можно ускорить или сразу перейти к результату.

## Как сохраняется занятие

Завершённая проверка автоматически сохраняет опыт до изменения бонуса, нового запуска или смены миссии. Наблюдение можно дописать позже; исходные условия, Q-таблица, путь и метрики остаются неизменными. Переключение разделов сохраняет введённый текст и не прерывает Worker. Смена миссии отменяет текущий расчёт и сохраняет завершённые опыты.

Первая завершённая пара сохраняется автоматически. Следующий эксперимент существует отдельно: прежняя пара вместе с объяснением остаётся в «Моих опытах», даже если новую тренировку остановили. Готовая новая пара заменяет её только после действия **«Заменить сохранённую пару»**. **«Начать заново»** явно очищает занятие.

В `localStorage` хранится только последнее занятие: выбранная миссия, черновики, завершённый опыт первой миссии, сохранённая пара и текущая пара. При перезагрузке восстанавливаются условия, завершённые результаты и записи; работающий Worker и промежуточная тренировка не возобновляются. Кадры анимации и скорость просмотра не записываются.

При восстановлении проверяются версия и размер данных, пресеты, форма и конечность Q, метрики и соответствие пути модели. Повреждённые данные или недоступное хранилище дают понятное предупреждение. Ошибка записи не выдаётся за успешное сохранение: текущие результаты остаются в памяти вкладки, но после перезагрузки последние изменения могут потеряться. Данные привязаны к адресу сайта и браузеру; очистка данных браузера удаляет занятие. Постоянного журнала многих занятий и экспорта пока нет.

## Запуск

Нужны Node.js 24 (проверен 24.16.0) и npm.

```sh
cd GoWeinerDog
npm ci
npm run dev
```

Открой адрес, напечатанный Vite, обычно http://127.0.0.1:5173. Если зависимости уже установлены, достаточно `npm run dev`. Остановка сервера: Ctrl+C в терминале.

Собранная версия:

```sh
npm run build
npm run preview -- --port 4173
```

Открой http://127.0.0.1:4173. Node нужен для разработки и локального сервера; сами вычисления идут в браузере. Открывать `dist/index.html` двойным щелчком через `file://` не нужно: модульному Worker нужен HTTP-сервер.

## Проверки

```sh
npm run typecheck
npm run test -- --run
npm run build
npm run test:e2e
```

Браузерные тесты используют установленный Google Chrome и production build из `dist`; конфигурация сама запускает локальный preview при необходимости. Перед ними выполни `npm run build`. Скриншоты и временные отчёты находятся в `test-results/`. Отдельный браузерный пакет не скачивается.

Для проверки опубликованной версии в отдельных пустых браузерных сессиях:

```sh
PLAYWRIGHT_BASE_URL=https://goweinerdog.vercel.app npm run test:e2e
```

С этой переменной локальный preview не запускается. Дополнительный тест проверяет анонимный HTTP-доступ, стили, изображения и настоящий Worker. При обычном локальном запуске три проверки публикации пропускаются. Тесты не используют занятие из твоего обычного браузера.

Проверки алгоритма, Worker, сохранности записей и контекста старого опыта сохранены. Перед публикацией прошли чистая установка `npm ci`, проверка типов, **183 модульных теста**, production build и 6 повторных проверок сохранённого контекста. На публичной версии **51 из 51 браузерной проверки прошла** за 3,1 минуты: обе миссии, исправленный просмотр старых опытов, восстановление, ресурсы и настоящий Worker при 1280, 375 и 320 px. Подробности и ограничения — в [docs/VALIDATION.md](docs/VALIDATION.md).

## Публикация обновлений на Vercel

Текущая папка связана с проектом `goweinerdog` в рабочей области `yelzhas-tem-s-projects`. Привязка находится в локальном `.vercel/project.json`; повторно создавать проект не нужно. Применены настройки проекта:

| Настройка | Значение |
| --- | --- |
| Framework Preset | Vite |
| Install Command | `npm ci` |
| Build Command | `npm run build` |
| Output Directory | `dist` |
| Node.js | 24.x |

Официальный Vercel CLI запускается через `npx`, отдельно от зависимостей приложения. Проверенная версия CLI — 60.1.3. После изменения кода в этой же папке:

```sh
npm ci
npm run typecheck
npm test -- --run
npm run build
npm run test:e2e
npx --yes vercel@60.1.3 deploy --prod --scope yelzhas-tem-s-projects
PLAYWRIGHT_BASE_URL=https://goweinerdog.vercel.app npm run test:e2e
```

Дождись состояния `Ready` и проверь публичную ссылку. Production-адрес остаётся тем же. Если CLI просит авторизацию, выполни `npx --yes vercel@60.1.3 login` и заверши вход в браузере; пароли и токены не надо записывать в проект или отправлять в чат. Если папка перенесена и привязка потерялась, используй существующий проект: `npx --yes vercel@60.1.3 link --yes --scope yelzhas-tem-s-projects --project goweinerdog`.

`vercel.json` не нужен: настройки заданы в проекте Vercel, а диапазон Node 24 закреплён также в `package.json`. `.vercelignore` исключает локальные зависимости, старую сборку, отчёты тестов и `.env*` из следующих загрузок CLI. Исходные тесты остаются доступными удалённой проверке типов. Официальные инструкции: [развёртывание через CLI](https://vercel.com/docs/cli/deploy), [исключение файлов](https://vercel.com/docs/deployments/vercel-ignore).

Размещаются статические файлы из `dist`; Q-learning продолжает работать в браузерном Worker. Сервер приложения, база данных, Supabase и регистрация не добавлены. Занятие остаётся в localStorage: оно отдельно для каждого браузера и адреса. Запись с localhost автоматически не переносится на публичный сайт; существующее локальное занятие сохраняется по прежнему адресу. Обновления по стабильной публичной ссылке не очищают localStorage.

## Где что находится

- `src/missions/index.ts` — две подготовленные площадки и отдельные пресеты; готовых маршрутов здесь нет. Настройки ловушки не меняют «Дорогу домой».
- `src/domain/environment.ts` — последствия одного шага: движение, ограждение, награда, домик.
- `src/learning/qLearning.ts` — как опыт изменяет оценку действия; `train.ts` — последовательность попыток.
- `src/learning/random.ts` — повторяемая случайность: один seed даёт ту же тренировку.
- `src/evaluation/evaluate.ts` — проход по выученной таблице без её изменения и случайного исследования.
- `src/workers/lab.worker.ts` — расчёт в отдельном потоке, чтобы кнопки оставались доступны.
- `src/app/labController.ts` — запуск, остановка и защита от результатов старого расчёта.
- `src/app/App.tsx` — три раздела, шаги занятия и связь действий пользователя с расчётами.
- `src/ui/TrainingGround.tsx`, `RoutePlayer.tsx` — площадка и просмотр массива переходов.
- `src/ui/ResultsPanel.tsx` — отдельные показатели домика, очков, выполненных шагов и входов к лакомству; расчёт по переходам.
- `src/ui/ExperimentComparison.tsx` — общий компонент двух опытов для лаборатории и «Моих опытов»: условия, результаты, записи, просмотр старых путей и объяснение.
- `src/ui/LearningGuide.tsx` — короткая справка для ученика.
- `src/experiments/lesson.ts` — состояние последнего занятия, неизменные снимки расчётов, обновление наблюдений, сохранение и проверка восстановленных данных.
- `src/experiments/session.ts` — исходный контракт снимков и сравнение всех условий пары; существующие проверки сохранены.
- `src/assets/pixel/` — собственные SVG таксы, домика, ограждений, дорожки и следов; `treat.svg` — пиксельное лакомство.

## Один шаг обучения

`новая Q = старая Q + α × (награда + γ × лучшая следующая Q − старая Q)`.

Например, `2 + 0.5 × (3 + 0.9 × 4 − 2) = 4.3`. Так алгоритм поправляет прежнюю оценку 2 на основе полученного опыта. При входе домой будущая оценка отсутствует: `2 + 0.5 × (3 − 2) = 2.5`. При ограничении шагов задача лишь прерывается, поэтому будущая оценка сохраняется.

Q-learning — машинное обучение с подкреплением: оценки действий вырабатываются по собственным действиям и наградам. Для 36 клеток × 4 действия нейросеть не нужна. Подробное объяснение и первичные источники — в [плане](docs/MVP_PLAN.md).

## Подтверждённые условия ловушки

Площадка 6×6: открыта верхняя дорожка из шести клеток, остальные клетки огорожены. Старт — строка 1, столбец 1; лакомство — строка 1, столбец 2; домик — строка 1, столбец 6. Бонус выдаётся при каждом фактическом входе, включая первый. Столкновение на этой клетке и пауза воспроизведения не дают лакомство.

Условия тренировки: 800 эпизодов, лимит 100 шагов на эпизод и на проверку, α = 0,2, γ = 0,9. Epsilon линейно уменьшается с 1 до 0,05 за первые 640 эпизодов, затем остаётся 0,05. Награда за шаг −1, дополнительный штраф столкновения −1, дополнительная награда за вход домой +12. Каждая тренировка начинается с нулевой Q-таблицы. В интерфейсе ловушки seed фиксирован: 42; другие seed из таблицы проверены тестами.

Первоначальный аналитический кандидат из плана подтвердился без подбора других условий: 12 отдельных обучений, по одному для каждой пары «seed × бонус». При +5 такса возвращается за лакомством; после изменения только бонуса на +1 новое обучение приводит к домику.

| Seed | Бонус +5: окончание / очки / шаги / входы | Бонус +1: окончание / очки / шаги / входы |
| --- | --- | --- |
| 0 | Лимит / 150 / 100 / 50 | Домик / 8 / 5 / 1 |
| 1 | Лимит / 150 / 100 / 50 | Домик / 8 / 5 / 1 |
| 7 | Лимит / 150 / 100 / 50 | Домик / 8 / 5 / 1 |
| 42 | Лимит / 150 / 100 / 50 | Домик / 8 / 5 / 1 |
| 2026 | Лимит / 150 / 100 / 50 | Домик / 8 / 5 / 1 |
| 65535 | Лимит / 150 / 100 / 50 | Домик / 8 / 5 / 1 |

Здесь «шаги» — выполненные шаги проверки. При лимите такса **до домика не дошла**. Эти результаты относятся к указанным условиям и набору seed; повторное проигрывание пути не считается независимым испытанием. В меню доступны целые бонусы от 0 до 10; приведённая проверка ловушки и исправления относится к +5 и +1.

## Самостоятельный эксперимент

1. Выбери «Ловушка лакомства», оставь бонус +5 и запиши прогноз: как лакомство повлияет на путь таксы?
2. Нажми «Начать тренировку», дождись завершения, затем «Посмотреть путь». Проверь отдельно домик, очки, выполненные шаги и входы к лакомству. Поставь просмотр на паузу и раскрой расчёт по шагам.
3. Запиши наблюдаемое поведение и нажми «Сохранить опыт и изменить бонус». Можно сразу изменить бонус: завершённый первый результат уже сохранён автоматически.
4. Выбери бонус +1. Запиши новое ожидание, начни тренировку с нуля и проверь новый путь.
5. Сравнение появится прямо в лаборатории. Сопоставь две карточки: изменён только бонус. Запиши наблюдение и объясни, почему поведение изменилось или осталось прежним; приложение не оценивает понимание по заполненному полю.
6. Открой «Мои опыты» и нажми «Путь опыта 1». У старого пути должны остаться бонус +5, 150 очков, 100 шагов и результат «До домика не дошла». Наблюдение можно дополнить.
7. Перезагрузи страницу: завершённая пара и записи должны восстановиться. Начни новый эксперимент, затем останови тренировку — прежняя пара и объяснение должны остаться в «Моих опытах».

## Проверка «Дороги домой»

1. Запиши прогноз, оставь seed 42 и начни тренировку.
2. Нажми «Посмотреть путь». Проверь три разных показателя: домик, очки и шаги.
3. Поставь просмотр на паузу, вернись к началу и пройди по одному шагу. Раскрой расчёт по шагам и сложи награды.
4. Запиши объяснение. Снова посмотри тот же путь: это воспроизведение, а не новый опыт.
5. Начни новое обучение и нажми «Остановить тренировку». Повторный запуск начинается с нулевой таблицы.
6. Измени seed: текущий опыт и путь сбросятся. Верни seed 42 и обучи снова — при одинаковых условиях результат воспроизводится.

Настройки «Дороги домой» сохранены отдельно: награда дома +20, за шаг −1, дополнительный штраф столкновения −1, γ = 0,95. После результата основное действие предлагает перейти к эксперименту с лакомством. Редактор, третья миссия «Новая прогулка», дополнительные настройки, журнал многих занятий и экспорт ещё не реализованы. Текущая доработка ограничена компоновкой и сохранностью последнего занятия; следующие этапы — только по отдельной команде. Новые зависимости для этой доработки не добавлялись.
